\chapter{Image Verbalization as a Cognitive Drone Pilot Copilot}
\label{chap:3}
\section{Introduction}

Drone navigation in unstructured indoor environments requires continuous scene
understanding: the system must recognise people, obstacles, and hazards from a
camera feed and translate that raw visual information into actionable safety
assessments. Traditional rule-based approaches rely on threshold comparisons
over sensor readings and cannot reason about context --- a wall at 0.5\,m and a
person at 0.5\,m are physically indistinguishable to a depth sensor, yet demand
different responses. Large language models (LLMs), trained on vast corpora of
natural language and visual descriptions, offer a different capability: given a
structured description of a scene, they can reason about what is present, why it
matters, and what a cautious pilot would do. \emph{Image verbalization} is the
process of converting a raw camera frame into such a structured natural-language
description, enriched with geometric and semantic metadata from computer vision
detectors, so that an LLM can reason over it. This chapter builds and validates
an image-verbalizing copilot: a hardware-software system that reads live
ESP32-S3-Sense camera frames, verbalizes what it sees, and produces a
\emph{suggested} pilot action --- one that the human operator accepts or
overrides. The LLM is a perception and reasoning assistant; authority over the
drone remains with the operator at all times.

The copilot is organised as four computational tiers
(Figure~\ref{fig:pipeline_architecture}): a 4\,kHz PID firmware layer, a
60\,fps MediaPipe emergency detector, a 3--4\,fps YOLO-World structural and
depth estimation layer, and a 0.1--0.4\,Hz LLM cognitive reasoning layer.
Each tier operates independently; the LLM never writes to the flight controller
directly. The chapter proceeds in three stages. First, the V-series experiments
isolate and optimise the LLM verbalization parameters ---
prompt technique (\S\ref{sec:v2}), output token budget and CLIP ablation
(\S\ref{sec:v6}), and scene context history (\S\ref{sec:v7}). A component
ablation study (\S\ref{sec:ablation}) then confirms which sensor inputs are
load-bearing for safety. The G-series experiments (\S\ref{sec:gseries}) integrate
all tiers into the full production copilot using the configuration derived from
the V~series, and evaluate action safety and cost at each integration stage.
H-series safety mechanism experiments (\S\ref{sec:hseries}) validate operator
trust and transparency features. The final production configuration ---
structured JSON prompt, \texttt{max\_tokens=256}, two-frame context history,
no CLIP, hybrid MediaPipe-triggered scheduling ---
is justified by experimental evidence before the first integrated pipeline result
is reported.

\section{LLM Verbalization Parameter Studies (V~Series)}
\label{sec:vseries}
% ==================================================================

The LLM cognitive tier is the most computationally expensive and
safety-critical component of the pipeline. Three configuration parameters are
optimised through controlled single-variable experiments before the integrated
system is assembled: prompt technique (\S\ref{sec:v2}), output token budget
(\S\ref{sec:v6}), and scene context history (\S\ref{sec:v7}). A fourth
parameter --- inference temperature --- is addressed in \S\ref{sec:v8}. Each
experiment holds all other parameters constant while varying one, using the
same eight canonical drone camera scenes captured from real
ESP32-S3-Sense hardware frames, five independent runs per condition.

\subsection{Prompt Technique (V2)}
\label{sec:v2}
% ------------------------------------------------------------------

and latency for single-pass safety classification. The structured JSON format
achieves the highest label accuracy, zero dangerous recommendations, and the
strongest internal reasoning consistency across 790 valid trials --- 4~models

YOLO-World + MediaPipe pipeline (\texttt{V2\_runs\_20260525\_035756.csv}).

Table~\ref{tab:v2_per_model} reports per-model best-technique results;

The structured format enforces 100\% reason-action alignment architecturally:
the JSON schema forces the model to commit to \texttt{risk\_level} and
\texttt{recommended\_action} as separate fields, making a response combining
\texttt{"risk\_level": "hazard"} with \texttt{"recommended\_action":
"PITCH\_FORWARD"} immediately self-contradictory and detectable as a parse
error. Structured produces the fewest unparseable outputs (16 no-action trials
versus 104 for CoT at 300~tokens).

Chain-of-thought reasoning quality is not inferior --- its reasoning-risk
alignment (96.0\%) is the highest of all techniques, and at 600~tokens Claude
CoT (60.5\%) exceeds Claude structured (43.6\%). The 300-token failure is a
methodological artefact: the reasoning fills the budget and the conclusion is
cut off. Structured is selected over CoT on operational grounds: it commits to
a parseable decision within the first $\sim$50~output tokens regardless of
budget, at approximately half the latency. Chain-of-thought inference reached
18,437\,ms at 300~tokens; at 600~tokens latency and API cost are approximately
doubled relative to structured. For a drone safety system where response time
and cost are first-class constraints, this overhead is not justified.

\textbf{Production decision:} Structured JSON is selected as the production
prompt technique for all models. Gemini's optimal technique is few-shot-3;
since Gemini structured also achieves 100\% action safety (55.0\% label
accuracy), structured is used uniformly across all four models for system
consistency.

\subsection{Output Token Budget and CLIP Ablation (V6)}
\label{sec:v6}

verbalization and pilot action within a single API call. Quality improves

and plateaus beyond 256 ($\Delta = 0.01/5$ from 256 to 512) across 640~trials per
condition on the YOLO-World pipeline

\textbf{CLIP ablation.}
A parallel run without CLIP (\texttt{V6\_runs\_noclip\_20260525\_201620.csv})
finds a maximum quality difference of $\Delta Q = 0.05/5$ across 640~trials
--- within experimental noise --- with an identical plateau at 256~tokens.
CLIP scores fall within $\pm$0.013 of the 0.200 uniform baseline across all
scene categories on 320$\times$240 frames: it provides no scene-discriminative
signal. In one configuration (Gemini at 128~tokens), removing CLIP
\emph{improves} quality by $+$0.40/5: the random CLIP label consumed reasoning
capacity within the constrained token budget, preventing the model from
concluding with a pilot action. CLIP also adds input token overhead on every
call with no measurable return.

\textbf{Production decisions:}
\begin{itemize}
  \item \texttt{max\_tokens\,=\,256} is selected as the minimum sufficient token
    budget (sufficient for all four models, adds negligible overhead over~512).
  \item CLIP is removed from the production pipeline. No G-series experiment
    includes a CLIP variant; the V6 ablation provides definitive evidence.
\end{itemize}

All four models achieve 100\% action safety and 100\% description accuracy
across all three history modes, confirmed from full LLM reply text. No
PITCH\_FORWARD recommendation occurs on any hazard frame across all 300~trials
regardless of history mode. History mode has no bearing on safety; the choice
of short over stateless is an accuracy argument only. The system exhibits
asymmetric change detection: hazard onset (person entering at frame~3) is
detected 100\% of the time by all models; hazard clearance (person leaving at
frame~5) is detected only 26.7\% of the time. Models classify the complex
indoor lab environment --- tables, chairs, equipment --- as caution or hazard
after the person departs. This asymmetry is architecturally correct: the system
over-lingers in HOVER rather than prematurely advancing, which is the
conservative failure mode appropriate for a safety-critical drone copilot.

Full history underperforms because the two identical safe frames at the
sequence start dilute the transition signal. For long missions, full history
also grows unboundedly with session length, increasing input token cost with
each call. Short history is bounded to exactly two frames and costs the same
regardless of mission duration.

\textbf{Production decision:}
Short history (two frames) is selected as the production default.

Temperature controls output randomness: in a safety-critical single-pass
classifier, the same scene should always produce the same risk label. V8 will
sweep temperatures $[0.0,\,0.2,\,0.5,\,0.8,\,1.0]$ across 800~trials to
identify the optimal production setting. The $t=0.2$ convention
\cite{yao2022react} was established for iterative ReAct agents where marginal
randomness helps escape incorrect reasoning steps; single-pass classification
has no equivalent justification for non-determinism. Temperature selection
carries zero API cost overhead, making the choice purely one of accuracy and
output consistency.

\section{Pipeline Architecture and Integration (G~Series)}
\label{sec:gseries}

DepthAnything~v2's incorrect 2.09\,m reading over its own visual analysis.
The architecture is correct; the depth sensor hardware is the bottleneck.

\subsubsection{Reasoning Quality (G5 Analysis)}
\label{sec:g5_reasoning}
% ----

Standard classification accuracy (59.2\% overall) is an inappropriate primary
metric for a drone safety system because it penalises over-caution and
under-caution equally. Over-caution causes the drone to hover unnecessarily ---
a conservative, safe outcome. Under-caution causes the drone to advance into
an obstacle --- a dangerous outcome. Action safety (97.5\%) is the primary
metric: it asks only whether the recommended pilot action is safe given the
ground truth, regardless of whether the risk label exactly matches the human
category assignment.

Evaluating reasoning quality across four dimensions --- description accuracy
(DA), reasoning-risk alignment (RRA), reason-action alignment (RAA), and action
safety (AS) --- reveals that the cognitive chain is internally sound at every
stage except initial visual perception. Table~\ref{tab:g5_reasoning} and
Figure~\ref{fig:g5_reasoning_radar} report the results.

mechanism that narrates the LLM's reasoning before each suggestion (\S\ref{sec:h4}).

\section{Chapter Summary}
\label{sec:ch3_summary}
% ==================================================================

The image verbalization pipeline converts raw 320$\times$240 drone camera
frames into structured pilot action suggestions through a four-tier hierarchy
spanning four orders of magnitude of latency: 0.001\,ms (PID), 16\,ms
(MediaPipe emergency detector), 275\,ms (YOLO-World + DepthAnything~v2), and
2,333--7,218\,ms (LLM cognitive tier). Table~\ref{tab:ch3_config} consolidates
the production configuration and the experiment justifying each parameter.

Under this configuration the integrated pipeline achieves \textbf{97.5\% action
safety} across 157~trials, with Gemini and GPT-4o-mini reaching \textbf{100\%}.
The dominant error mode is conservative over-caution (41/157, 26\%), not
dangerous under-caution (3/157, 1.9\%). All three genuinely dangerous
recommendations arise from a single source: GPT-4o anchoring to
DepthAnything~v2's incorrect 2.09\,m depth reading for a wall at 20\,cm.
Reasoning quality analysis confirms all four LLMs achieve
\textbf{100\% reason-action alignment} (Table~\ref{tab:g5_reasoning}) ---
the cognitive layer is internally sound; failures trace to 320$\times$240
visual perception ambiguity, not to reasoning errors. At the production Gemini
rate of 0.4\,Hz, continuous drone operation costs approximately
\textbf{\$0.17/hour} in API calls. The pipeline architecture, production
configuration, cost analysis, and safety properties established in this chapter
constitute the perceptual foundation for the cognitive flight control system
presented in Chapter~\ref{chap:4}.
